# 环境体检报告（对照《第三版执行计划》环境基线）

> **结论一句话**：当前开发机**远不符合**计划要求——**没有任何 Linux 运行时**（WSL 未安装、无 Docker、无 Linux VM），因此 **Wave 0 与 Wave 1 完全阻塞**。可用部分只有 Windows 侧的 C++/CMake/Node 工具链与一个**版本偏低**的 Redis。
>
> **取证方式**：全部结论来自本轮实机命令输出（见各节「证据」）。未取到证据的项标注为"未验证"。

## 二、Linux 运行时（阻塞项，最关键）

**证据 1** — `wsl.exe -l -v` / `wsl.exe --status` 输出：

```
未安装适用于 Linux 的 Windows 子系统。可通过运行 “wsl.exe --install” 进行安装。
有关详细信息，请访问 https://aka.ms/wslinstall
```

> 注意：是**整个 WSL 子系统未安装**（不是"装了但没发行版"）。

**证据 2** — `command -v docker` → 无；`/c/Program Files/Docker/Docker/resources/bin/` → 不存在。→ **Docker 未安装**。

**证据 3** — `ls "/c/Program Files (x86)/VMware"` → 仅 `VMware VIX`（API 层）；无 `vmware`/`vmplayer`/`vmrun` 命令，无 VirtualBox。→ **无可用的桌面虚拟机**。

**证据 4** — WSL 功能开关查询（`Get-WindowsOptionalFeature`）返回「**该操作需要提升**」（需管理员），故功能开关状态**未取到**；但由证据 1 已可判定 WSL 未安装。

**旁证** — 虚拟化平台：`HypervisorPresent=True`（有 hypervisor 在运行，对安装 WSL2 是**有利**信号）。

> **影响**：计划 Wave 0 的 8 条冒烟测试（`unshare` / cgroup v2 / seccomp / `pivot_root`）**一条都跑不了**；Wave 1 的沙箱核心同样阻塞。

## 四、Redis（在跑，但版本是坑）

**证据 5** — `D:\redis\` 为 **tporadowski/redis 的 Windows 移植版**，`RELEASENOTES.txt` 载明：

```
2021-10-18: Redis 5.0.14 for Windows
https://github.com/tporadowski/redis/releases/tag/v5.0.14
```

**证据 6** — 实例正在运行（`netstat`：`127.0.0.1:6379 LISTENING`，需认证）。用本机配置口令 `INFO server` 复核：

```
redis_version:5.0.14.1
redis_mode:standalone
os:Windows
arch_bits:64
```

**证据 7** — 关键命令存在性实测：

| 命令 | 结果 | 说明 |
|---|---|---|
| `XADD` | 存在 | Streams 基础（5.0+）|
| `XGROUP` / `XREADGROUP` / `XPENDING` / `XCLAIM` | 存在 | 消费组 + PEL 可用 |
| **`XAUTOCLAIM`** | **`ERR unknown command 'xautoclaim'`** | **不存在——该命令是 Redis 6.2 才引入** |

> **对计划的影响（重要）**：计划**任务 2.2「XAUTOCLAIM 10 分钟窗口」在本机 Redis 上无法实现**。
> 两条出路：
> 1. **升到 Redis 7.x**（推荐，随 WSL 一起装）——任务 2.2 原样可用；
> 2. 若坚持留在 5.0：把 2.2 改为「`XPENDING` 扫描 idle 超阈值 → 用 `XCLAIM` 认领」——5.0 可行，但代码更啰嗦、扫描更重。

**证据 8** — MySQL：无 `mysqld`/`mariadb` 命令、无 `/c/Program Files/MySQL`、`3306` 无监听 → 未安装。

## 五、恢复路径（按推荐度排序）

### 方案 A：WSL2 + Ubuntu 22.04（推荐）

```powershell
# 管理员 PowerShell
wsl --install -d Ubuntu-22.04
# 重启后进入 Ubuntu，安装依赖：
```

```bash
sudo apt update
sudo apt install -y build-essential cmake ninja-build redis-server mysql-server \
                    libseccomp-dev libcap-dev libargon2-dev libhiredis-dev
```

- 优点：最接近原生 Ubuntu，命令行体验与计划一致；`HypervisorPresent=True` 说明条件具备。
- 代价：需**管理员权限 + 重启**。
- 装完须在 **WSL 内**重跑本报告的 1/5/6/7/8 项复核（Windows 侧的结论不迁移）。

### 方案 B：Docker Desktop

- 适合 Wave 5 部署联调；但**容器内再建 cgroup 子树需 `Delegate=yes` 或 `--privileged`**，不适合 Wave 0 早期验证。

### 方案 C：VMware + Ubuntu 22.04 VM

- 当前仅有 VMware VIX（API），**需先安装 Workstation/Player**；再建 Ubuntu VM。

## 六、下一步（建议顺序）

1. 选 A/B/C 之一并落地 —— 推荐 **A（WSL2）**。
2. 落地后在 Linux 内**重跑** Wave 0 的 8 条冒烟（本报告只证明了"Windows 上不行"，没证明"WSL 里行"）。
3. Redis 升到 7.x（否则需改计划任务 2.2）。
4. 把结果回填到《第三版执行计划.md》的「零点五」与 Wave 0 验收表。
